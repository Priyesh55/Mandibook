# AI Contribution Log

An honest record of what AI did on Mandi Book, what failed, and what humans decided. Tools: Claude Code for implementation (the model named in the commit trailers is Claude Sonnet 5.5), and ChatGPT (OpenAI) for planning, architecture discussions, prompt preparation and technical review; the owner confirmed this description as accurate on 30 October 2026. No ChatGPT conversation is stored here, so the use cannot be verified from the repository, and no application code is claimed to have been generated or committed by ChatGPT (`docs/PROVENANCE.md` section 4). The project owner makes the decisions and approves the rules.

## What this log can and cannot show
- The ORIGINAL development repository (not this one) had 10 commits (2026-10-17 to 2026-10-20), each with a Claude co-author trailer, plus a large body of uncommitted work. THIS submission repository starts with a snapshot commit of that working tree and contains only its own commits, all dated 2026-10-26 (`git log`; the first audit saw five, later commits are listed there too); see `docs/PROVENANCE.md` §1. Neither history can show line-level proportions, so this log does not claim that every line was generated by AI. Implementation and tests were written by the AI agent in sessions directed by the owner; verification results are recorded in `QA_EVIDENCE.md` with the session they came from.
- Prompts and transcripts are not stored in the repository, and none are reproduced here.

## Human decisions (not AI)
- Product direction: Aadat billing first, English and Hindi, lot-wise goods, purchasers and expenses on the bill.
- Safety boundaries: synthetic data only; no real business data in the repository or tests; no invented financial rules.
- 2026-10-19: audit retention is permanent.
- 2026-10-20: security architecture approved (authentication, OWNER/EMPLOYEE roles, separate platform administrator, restricted runtime database role).
- 2026-10-25: the owner personally confirmed, in a development session, three rules: 5 % commission, rate per 100 kg, per-piece expenses (`business-rules.md`). The rounding details (BR-002 to BR-006) were recorded earlier in the project instructions and are not part of that explicit confirmation. The approval is a session message; the repository stores only this record. Before the confirmation, the agent's documentation had called the whole rule set "owner-confirmed" without a stored approval; the records were corrected the same day.
- Which migrations may be applied to the persistent development database: only with the owner's go-ahead and a verified backup.
- 2026-10-30: the owner confirmed the per-piece expense rule: one expense-head rate applies across all lots (BR-005c), each lot's expense is calculated independently as lot size x rate and rounded per lot (BR-005a, BR-005b), and the lots' amounts are summed for the bill. The implementation was inspected and left unchanged; it aggregates pieces and rounds once, which differs from the confirmed rule for some rates with three or four decimals (known limitation LIM-1 in `business-rules.md`). Only whether "lot size" always means pieces remains open (BR-110). Like the earlier confirmations, this is a session message and the repository stores only this record.
- 2026-10-30: the owner confirmed that the ChatGPT disclosure is accurate, said they are unsure about the full scope and provenance of the investigation of the older program, and, later the same day, confirmed that none of the eight synthetic test passwords in the secret-scanner allow-list is used for any real account or system and **approved all ten existing allow-list entries** for this submission (8 synthetic test passwords, 2 documented false positives). Entries and hashes were not changed.
